# ЧАСТЬ 0. СНАЧАЛА ПОНЯМИТЕ, ЧТО ТАКОЕ САЙТ

Представьте **офис**.

| В реальной жизни | В компьютере |
|---|---|
| Посетитель, который заходит в офис и просит документ | **Браузер** (Chrome, Edge) — программа, где вы видите сайт |
| Администратор, который сидит внутри и отвечает | **Сервер** — программа на компьютере (`runserver`) |
| Инструкции администратора, что делать с просьбой | **Python-код** (`views.py`) |
| Шаблон бланка, куда вписываются данные | **HTML-шаблон** (`home.html`) |
| Огромный архив с папками и документами | **База данных** (`db.sqlite3`) |
| Правила, как заполнять бланк | **Форма** (`forms.py`) |
| Описание, какие бывают документы | **Модели** (`models.py`) — описание таблиц БД |
| Список кабинетов и указателей | **URL'ы** (`urls.py`) — адреса страниц |

## Как происходит один клик

1. Вы вводите в браузере `http://127.0.0.1:8123/` и жмёте Enter.
2. Браузер отправляет **запрос** (request) серверу: «дай мне главную страницу».
3. Сервер смотрит `urls.py`: «ага, адрес `/` — значит надо вызвать функцию `home`».
4. Функция `home` из `views.py` идёт в базу данных (`db.sqlite3`) и берёт оттуда цифры.
5. Функция отдаёт эти цифры шаблону `home.html`.
6. Шаблон собирает готовый HTML-код страницы.
7. Сервер отправляет **ответ** (response) браузеру.
8. Браузер показывает вам красивую страницу.

**Вся магия Django — в этих 8 шагах.** Весь код нужен только для того, чтобы обслуживать эти шаги.

## Что такое Python одной фразой

Python — это язык, на котором пишут **инструкции для компьютера**. Файл `.py` — просто текстовый файл с инструкциями. Ничего волшебного: вы пишете слово, компьютер его выполняет.

## Главные слова, которые встретятся в коде

| Слово | Простыми словами |
|---|---|
| `import` | «принеси мне инструмент из другой коробки». Например `import os` — принести инструмент для работы с операционной системой |
| `def` | «создай функцию» — именованную пачку инструкций. `def home():` → функция с именем `home` |
| `return` | «верни результат» — закончить функцию и отдать ответ |
| `class` | «создай класс» — чертёж/шаблон объекта. От класса делаются конкретные объекты |
| `self` | «этот самый объект» — обращение к самому себе внутри класса |
| `= ` | «положить значение в коробку с именем». `x = 5` → в коробку `x` положить пятёрку |
| `if` | «если условие правда — сделай это, иначе — то» |
| `for` | «для каждого элемента в списке сделай одно и то же» |
| `dict` (`{}`) | «коробка с подписями»: `{'name': 'Urals'}` — по ключу `name` лежит значение `Urals` |
| `list` (`[]`) | «список значений подряд»: `[1, 2, 3]` |
| `str` | текст (строка). `str(5)` → превратить число 5 в текст «5» |
| `#` | комментарий — компьютер не читает, это заметка для человека |
| `'''` или `"""` | многострочный комментарий (докстринг) |
| `None` | «ничего», пустота, отсутствие значения |
| `True / False` | да / нет |
| `.` (точка) | «возьми у объекта его часть». `user.username` → у пользователя взять имя |
| `()` | вызов функции: `print()` — выполнить функцию print |
| `[]` у списка/словаря | достать по номеру или по ключу: `data['name']` |

## Django-слова

| Слово | Что означает |
|---|---|
| **model** (модель) | описание одной таблицы в базе данных в виде класса Python |
| **field** (поле) | одна колонка таблицы: `name = models.CharField(...)` |
| **migration** (миграция) | файл-инструкция, как создать/изменить таблицу в БД |
| **view** (представление) | функция или класс, который обрабатывает запрос и отдаёт ответ |
| **template** (шаблон) | HTML-файл с вставками `{{ переменная }}` и `{% if %}` |
| **form** (форма) | описание полей, которые пользователь заполняет на сайте |
| **context** (контекст) | коробка с данными, которую view передаёт в шаблон |
| **queryset** | «запрос к базе» — выборка записей. `Well.objects.all()` |
| **pk** | primary key — уникальный номер записи (ID). `w.pk` = `w.id` |
| **FK** (ForeignKey) | ссылка на запись из другой таблицы |
| **CSRF** | защита: скрытое поле в форме, без которого Django не даст сохранить данные |
| **static** | файлы, которые не меняются: CSS, картинки |
| **request** | всё, что прислал браузер: адрес, кнопки, куки, пользователь |
| **POST / GET** | GET — «покажи страницу» (данные в адресе), POST — «прими данные из формы» |

# ЧАСТЬ 1. ОБЕИХ ПРОЕКТОВ — ОДНА И ТА ЖЕ СХЕМА

У обоих проектов одинаковый «скелет»:

```
ПРОЕКТ/
├── manage.py              ← пульт управления: запуск сервера, миграции
├── db.sqlite3             ← сама база данных (файл)
├── oilproject/  или  refinery_project/   ← НАСТРОЙКИ всего сайта
│   ├── settings.py        ← главные настройки (БД, язык, приложения)
│   ├── urls.py            ← главный указатель адресов
│   ├── wsgi.py / asgi.py  ← технические файлы для запуска (не трогаем)
│   └── __init__.py        ← пустой файл-метка «это папка Python»
└── wells/  или  refining/   ← ПРИЛОЖЕНИЕ (бизнес-логика)
    ├── models.py          ← описание таблиц БД
    ├── forms.py           ← формы
    ├── views.py           ← логика: что делать с запросом
    ├── urls.py            ← адреса этого приложения
    ├── admin.py           ← настройка админки
    ├── tests.py           ← тесты
    ├── apps.py            ← настройка приложения
    ├── migrations/        ← автоматически созданные файлы БД
    ├── templates/         ← HTML-страницы
    └── static/            ← CSS (только в моём проекте)
```

**Запомните главное различие:**

- В проекте 2 шаблоны лежат **внутри** приложения: `wells/templates/home.html`.
- В моём проекте шаблоны лежат **в корне**: `templates/refining/home.html`.

Оба варианта работают — просто настройка `DIRS` в `settings.py` разная.

## 2.3. Файлы `urls.py` — указатели адресов

```python

2  from django.urls import path, include
```

### `wells/urls.py` (приложения)
```python

2  from django.contrib.auth.views import LogoutView
3  from . import views
```

`.` означает «из этой же папки». То есть `from . import views` — принести `views.py` приложения `wells`.

**Это ключевая особенность проекта 2**: у каждой скважины есть владелец.

```python
        cleaned_data = super().clean()
        input_volume = cleaned_data.get('input_volume')
        output_volume = cleaned_data.get('output_volume')
```

```python

    SULFUR_PENALTY = 2.5

    def calculate(self):
        data = self.cleaned_data
        base = self.YIELDS.get(data['process_type'], 50)
        sulfur = float(data['crude_oil'].sulfur)
        efficiency = max(20.0, base - sulfur * self.SULFUR_PENALTY)
```

# ЧАСТЬ 6. ВОЗМОЖНЫЕ ВОПРОСЫ ПРЕПОДАВАТЕЛЯ И ОТВЕТЫ

**«Что вы делали?»**
> Сделал веб-приложение на Django для учёта нефтепереработки. Есть база из 5 таблиц, регистрация и вход, формы добавления данных и калькулятор выхода продукта.

**«Какая СУБД? Почему?»**
> SQLite. Она встроена в Python, не требует установки сервера, данные хранятся в одном файле `db.sqlite3`. Для учебного проекта этого достаточно. При необходимости легко заменить на PostgreSQL — поменять `DATABASES` в `settings.py`.

**«Сколько таблиц в базе?»**
> Пять прикладных: НПЗ, марки нефти, установки, продукты, партии. Плюс служебные таблицы Django для пользователей, сессий и админки — всего 16.

**«Как работает авторизация?»**
> Django хранит пользователей в таблице `auth_user`. После входа создаётся сессия в `django_session` и кука в браузере. Вiew проверяет `request.user.is_authenticated`; не вошедших `@login_required` или `LoginRequiredMixin` отправляет на `/login/`.

**«Что такое миграция?»**
> Файл с инструкцией, как создать или изменить таблицу в базе. Django сам его генерирует из `models.py` командой `makemigrations`, а `migrate` применяет к файлу БД.

**«Чем модель отличается от формы?»**
> Модель — это структура таблицы в базе. Форма — то, что видит пользователь на странице. `ModelForm` строит форму по модели автоматически.

**«Что такое FK?»**
> ForeignKey — ссылка на запись другой таблицы. Например, партия ссылается на НПЗ, сырьё, установку и продукт. При удалении НПЗ можно настроить, что делать с партиями (`CASCADE`, `PROTECT`, `SET_NULL`).

**«Почему в форме `{% csrf_token %}`?»**
> Это защита от поддельных запросов (CSRF). Django вставляет скрытое поле с уникальным кодом и не примет POST без него.

**«Как посчитать выход продукта?»**
> В модели `ProductionBatch` есть свойство `yield_percent`: выход продукта / сырьё × 100, округлённое до двух знаков.

**«Чем отличаются ваши два проекта?»**
> Проект 2 про добычу (скважины и добыча), 2 таблицы, данные разделены по пользователям, простенький светлый интерфейс, class-based views, фильтры по датам. Мой — про переработку, 5 таблиц, общие данные, тёмная адаптивная тема, калькулятор, демоданные и тесты. Стек одинаковый: Django + SQLite.

# ЧАСТЬ 9. ЧТО ДЕЛАТЬ, ЕСЛИ ПРОСЯТ ИЗМЕНИТЬ КОД БЕЗ МЕНЯ

## Универсальный алгоритм на любой случай

1. **Не паникуйте и переспросите:** «Правильно ли я понял, что нужно поменять ...?»
2. **Найдите файл** по таблице ниже (откройте в PyCharm правой кнопкой → Open in Preview).
3. **Найдите готовый похожий кусок кода** и скопируйте его, поменяв 1–2 слова. Так делают все программисты.
4. **Если тронули `.py`** — перезапустите сервер. Если только HTML/CSS — обновите страницу Ctrl+F5.
5. **Если тронули `models.py`** — обязательно `makemigrations` и `migrate`.

## Рецепт 1. «Поменяйте цвет кнопки»

**Проект 2 (скважины):** `wells\templates\base.html`, самый верх, блок `<style>`.
Найдите в начале:

```css
:root {
    --orange: #f9a826;
}
```

Поменяйте `#f9a826` на другой код цвета — и **все** оранжевые элементы сразу станут новыми.
Например синий: `--orange: #3b82f6;`. Красный: `--orange: #e74c3c;`.

**Мой проект (переработка):** `refining\static\refining\style.css`, самая первая строчка `:root`:

```css
:root {
    --orange: #ff8a1f;
}
```

Меняете значение — и цвет кнопок, ссылок и акцентов меняется везде.

> Это самый частый вопрос. Ответ: «Цвет задаётся CSS-переменной в блоке `:root`, я меняю одно значение, и оно применяется ко всему сайту».

## Рецепт 2. «Поменяйте надпись / текст»

| Что поменять | Проект 2 | Мой проект |
|---|---|---|
| Название в шапке | `wells/templates/base.html`, строка `<span>Нефте<b>Дашборд</b></span>` | `templates/refining/base.html`, блок `.brand` |

## Рецепт 3. «Добавьте новую страницу»

Делается в 4 шага. Скопируйте этот пример и поменяйте имена.

**Шаг 1.** `views.py` — добавьте в конец:

```python
from django.shortcuts import render

def my_page(request):
    return render(request, 'my_page.html')
```

(Если импорт `render` уже есть вверху — второй раз писать не надо.)

**Шаг 2.** `urls.py` — добавьте в список `urlpatterns`:

```python
path('my-page/', views.my_page, name='my-page'),
```

**Шаг 3.** Создайте новый файл:
- проект 2: `wells/templates/my_page.html`
- мой проект: `templates/refining/my_page.html`

Содержимое:

```html
{% extends 'base.html' %}
{% block title %}Моя страница{% endblock %}
{% block content %}
<h2>Моя страница</h2>
<div class="card">Здесь что угодно.</div>
{% endblock %}
```

**Шаг 4.** Добавьте ссылку в меню `base.html`:

```html
<a href="{% url 'my-page' %}">Моя страница</a>
```

В моём проекте из-за пространства имён будет `{% url 'refining:my-page' %}`, а в `base.html` путь к шаблону в `extends` — `'refining/base.html'`.

Перезапустите сервер (если меняли `.py`) и откройте `/my-page/`.

## Рецепт 4. «Добавьте поле в таблицу»

1. `models.py` — допишите поле в нужный класс, например:

```python
comment = models.CharField('Комментарий', max_length=200, blank=True)
```

2. В терминале:

```
py manage.py makemigrations
py manage.py migrate
```

3. Добавьте это поле в `forms.py` в кортеж `fields`.
4. Перезапустите сервер. Поле появится в форме и в базе.

`blank=True` означает «можно не заполнять».

## Рецепт 5. «Измените расчёт / логику»

| Что просят | Проект 2 | Мой проект |
|---|---|---|
| Статистику на главной | `wells/views.py`, метод `HomeView.get_context_data()`, строки с `Sum` | `refining/views.py`, функция `home()` |
| Формулу калькулятора | калькулятора нет | `refining/forms.py`, класс `YieldCalculatorForm`, словарь `YIELDS` |
| Проверку формы | `wells/forms.py`, метод `__init__` | `refining/forms.py`, метод `clean()` |
| Список скважин/записей | `wells/views.py`, методы `get_queryset()` | `refining/views.py`, `_handle_form()` и списки |

Например, чтобы поменять коэффициент в калькуляторе, найдите:


и поставьте другое число. Всё.
